# 下载推特(X)视频(GIF)

用户提供推特(X)的推文链接，如果它带有视频(GIF)则下载，并保存到输出目录。（注意：输出目录也请遵循 output_storage.md 的规则与限制）

下载完成的页面，提供「视频转 GIF」的功能按钮，可以将刚下载的视频直接转换成 GIF，让两个功能可以串联起来。

带 `/video/序号` 链接的下载范围选择自 1.3.2 起提供，记录于 [CHANGELOG 的 1.3.2 条目](../CHANGELOG.md#132)。

登录限制识别与可选 X 登录自 1.3.3 起提供，记录于 [CHANGELOG 的 1.3.3 条目](../CHANGELOG.md#133)。登录态跨重启保存、登录首屏与表单布局修复自 1.3.4 起提供，记录于 [CHANGELOG 的 1.3.4 条目](../CHANGELOG.md#134)。

## 使用流程

1. 首页“图片”分类中选择“下载推特视频（GIF）”（位于“图片拼接”之后），粘贴一条推文链接；也可从 X、浏览器等应用分享文本到同名 Natsuko 分享目标。
2. 链接可带分享文案和查询参数，支持 `x.com`、`twitter.com` 及其 `www`、`mobile`、`m` 子域的 `/用户名/status/编号`、`/i/status/编号`、`/i/web/status/编号`、`/statuses/编号`，也接受末尾的 `/video/序号` 或 `/photo/序号`。输入文本最多 8192 个字符；相同链接去重，一次输入多个不同推文链接，或同一推文的不同 `/video/序号` 链接时会报错，不会静默选择其中一个。同一推文的普通链接与单个视频链接同时出现时，保留该视频的定位信息。不支持 `t.co` 短链接、用户主页、搜索页或直接视频地址。
3. 点击“开始下载”，先解析可获取的媒体。X 明确要求登录后查看时，询问是否登录；同意后在 X 官方页面完成登录与验证，点击“登录完成，继续”，再获取媒体信息。取消登录或关闭询问框会返回输入页并保留链接。其他失败按下文分类报错，不统一引导登录。
4. 链接带 `/video/序号` 且推文包含多个视频或 GIF 时，弹窗选择“只下载当前视频”或“下载全部视频”；确认前不会下载视频或创建输出批次目录，取消弹窗返回输入页并保留链接。推文只有一个视频时直接下载，不额外弹窗；普通推文链接和 `/photo/序号` 链接继续下载推文中的全部视频。下载时显示当前视频、字节进度与校验状态，允许取消；多个视频分别保存并报告单个视频的失败。取消会放弃本次下载批次，清理尚未交付到结果页的文件，保留输入链接供重试。
5. 完成页可打开、分享视频，查看实际保存位置或修改链接继续下载。X 的 GIF 动图按平台提供的 MP4 保存，下载阶段不转码。
6. 每个成功视频都有“视频转 GIF”按钮，点击后直接进入现有 GIF 参数配置页，无需再次选择文件；支持帧率、采样间隔、尺寸与循环设置。使用保留的应用专属视频副本，转换不删除源视频。配置页返回可恢复原下载结果并选择其他视频。

`/video/序号` 按推文原始媒体附件位置匹配，图片也占用这个位置序号；例如依次为图片、视频、视频时，`/video/3` 指向第二个视频。序号不存在或对应的是图片时，明确报告无法找到指定视频，不会自动下载另一个视频；可改用不带媒体后缀的推文链接下载全部视频。视频是否有可下载的 MP4 不改变它的位置或本次视频数量，缺少 MP4 仍按单个视频报告失败。

分享导入只接受 `ACTION_SEND` 的 `text/plain`，读取 `EXTRA_TEXT` 与 `ClipData.text`，不读取分享的文件 URI。分享后保留下载确认步骤，使用相同的登录判断与下载范围选择；处理、等待登录或范围选择、保存期间的新导入不会替换当前任务。当前页面有尚未导出的图片调整时，先询问是否放弃编辑：取消保留编辑并丢弃待导入链接，确认后才进入该链接的下载确认页。无效链接只显示错误，不清除已有编辑。

## 登录与访问限制

默认先匿名读取公开元数据。信息不足时，再读取 X 官方推文网页中的结构化响应；只使用与请求推文编号匹配的结果，不执行页面脚本，也不以页面里出现“登录”按钮、其他推文内容或 HTTP 状态码作为登录限制的证据。

未持有登录态时，下载页同时提供「登录 X」入口。用户可以主动登录，再尝试无法确认原因的链接；这不会将未知原因判定为登录限制，也不保证登录后可访问。此入口直接打开同一官方登录页；完成后返回输入页并保留链接，需要用户点击“开始下载”，不会自动启动下载。

| X 返回的证据 | 应用行为 |
| :-- | :-- |
| 当前推文明确返回 `NsfwLoggedOut`，或媒体占位信息明确要求登录查看 | 询问用户是否登录；同意后打开官方 X 登录页，取消保留链接。 |
| 明确报告内容删除或不存在 | 报告删除／不存在，不询问登录。 |
| 明确报告作者限制可见、保护的推文 | 报告访问权限限制，不询问登录；登录本身不会获得作者授权。 |
| 明确的年龄、账号设置或地域限制 | 报告对应限制，不反复要求登录；登录不能改变账号年龄或解除地域限制。 |
| 作者或推文不可用、限流、网络错误 | 报告对应错误，不把它们当作登录限制。 |
| 空对象、空 `TweetTombstone`、未识别响应、普通 HTTP 401/403/404 | 无法单凭这些信息判断原因；在可用的官方元数据中补充判断，仍无证据时报告原因未知或请求错误，不推断删除或要求登录。 |

例如 `2120307161339244627` 的匿名 syndication 响应只有空 `TweetTombstone`，这一响应本身不能说明原因。2026-11-11 的 X 官方网页中，同一推文的结构化 `BlurredMediaTombstone` 明确提示年龄受限媒体需要登录查看，因此可以触发登录询问。解析时必须匹配推文编号；固定测试夹具只保留相关结构，不保存登录信息。

登录页通过受限 WebView 打开 X 官方公开入口 `https://x.com/`，由用户选择网页上的「登录」，再输入用户名、密码并完成验证。初始导航不直接进入 X 的内部 onboarding 子步骤。支持 X 自身的登录与双重验证，不支持 Google / Apple 外部登录。Natsuko 不读取密码，也不注入 JavaScript 原生桥；禁止文件和内容 URI、非 HTTPS 导航、外部应用跳转及弹出窗口，证书验证失败即停止。用户点击“登录完成，继续”后，仅提取元数据请求所需的 `auth_token` 与 `ct0`，两者缺一或无效时继续停留在登录页。

原生 `TwitterSession` 仅包含 `auth_token` 与 `ct0`，使用 Android Keystore 中的 AES-GCM 密钥加密后原子写入应用私有 `noBackupFilesDir`，不写入普通偏好、UI 保存状态或日志，不参与云备份和设备迁移。已完成的登录跨应用重启、进程结束和 ViewModel 重建保留，不设置额外的本地过期时间；后续请求仍由 X 验证登录态是否有效。下载页提供“清除 X 登录态”，主动清除或 X 明确报告认证失效时同时移除内存和持久记录。启动恢复、保存和清除均在后台执行。每次账号操作或开始下载前重新读取持久记录，等待最新登录态同步完成；一个入口清除登录态后，其他页面的下次下载不会复用旧内存会话，其他入口新保存的登录态也会在下次操作时读取。保存失败明确报错，不将仅存于内存的会话显示为已保存。

WebView 自身可能短暂把 Cookie 和网页数据写入应用私有目录，因此在每次打开和关闭时清理，并从云备份与设备迁移中排除 `app_webview/`；这不删除已加密保存的原生登录态。旋转等配置重建后会重新打开干净的登录页，尚未完成的网页登录需要重来。登录页不显示常驻的说明文字或信息展开／收起按钮，将空间留给 X 网页。原生标题、错误提示和操作按钮与网页分区排布，网页使用独立的有界、裁剪视口。创建 WebView 后、首次加载和挂载前，显式将原生 `LayoutParams` 的宽高设为 `MATCH_PARENT`，并启用 `useWideViewPort` 与 `loadWithOverviewMode`，使网页视口声明参与尺寸计算。主文档加载期间，在标题与网页之间显示独立的加载提示；WebView 创建完成不等于网页已加载，发生主文档错误时结束加载提示并显示错误。该状态只反映 WebView 主文档加载，不能保证 X 后续异步登录步骤已完成。键盘弹出、小屏幕及大字体时，提示区与网页区仍不重叠，网页内的表单可滚动操作。

只有 X 的结构化响应明确报告认证失效时，才先清除会话并重新匿名判断；普通 HTTP 401/403、网络错误、内容不可用及未知错误均保留已保存登录态。清除失效会话后，只有再次确认当前内容需要登录，才询问重新登录。每次下载最多发起一次交互登录，登录后仍受限会给出实际错误，避免循环弹窗。等待同意、登录、范围选择时均可取消，保留原链接，不创建输出目录；没有用户确认不会获取账号登录态。登录不能保证账号有权查看所有受限内容。

## 保存规则

- 首先保存到应用专属 `Pictures/Natsuko/DownloadTwitterVideo/<时间戳>/`，文件名为 `twitter_<推文编号>_<视频序号>.mp4`。文件名的视频序号从 1 开始，图片不占用序号；只下载指定视频时仍保留它在推文中的原视频序号，某个视频失败后，后续视频也保留原序号。
- 默认不生成公共副本。开启“保存至用户存储目录”后，自动保存到 `Download/Natsuko/DownloadTwitterVideo/`，或自定义根目录下的 `DownloadTwitterVideo/`，不再增加时间戳目录。
- 结果页开启开关可立即补存本次成品；用户目录失败保留应用专属视频，可逐文件重试，已成功保存的文件不会重复复制。自定义目录仍通过系统目录选择器取得持久读写授权。
- 串联转换产生的 GIF 写入应用专属 `VideoToGif/<时间戳>/`，沿用当前保存设置，用户目录副本直接写入 `VideoToGif/`；原 MP4 继续保留。具体授权、保留和重试行为遵循 [输出存储](output_storage.md)。

## 实现与支持范围

- 使用 X 自家的 `cdn.syndication.twimg.com/tweet-result` 公开嵌入接口及官方推文网页解析媒体和访问状态。用户确认登录后，仅向固定 X 元数据接口发送必要账号 Cookie；不向 syndication、视频 CDN 或重定向目标转发登录态，不使用第三方解析站。常规视频选择接口返回的最高码率 MP4；同码率时优先较大分辨率。
- 已登录时也优先复用公开解析结果；至少一个视频有 MP4 时保留整个媒体列表与逐视频失败，不因诊断接口故障丢弃已能下载的视频。公开信息不足时，匿名流程通过 `https://api.x.com/1.1/guest/activate.json` 获取访客令牌，并请求固定的 `https://x.com/i/api/graphql/<操作编号>/TweetResultByRestId`；有用户会话时只在该固定 GraphQL 请求中使用账号凭据。当前操作编号与请求参数维护在 `TwitterWebMetadata`，不是用户密钥；接口更新须同步域名／路径限制及测试。匿名 GraphQL 仍无明确原因时再读取当前推文的官方网页。
- 网络代码只负责元数据请求与字节下载。下载先写入临时文件，由共享 `FfmpegVideoEngine.probe` 调用随包 FFprobe 校验有效视频流、尺寸和时长后才作为成品提交，不引入 Android 系统媒体处理路径。
- 文件以流方式写盘，限制 HTTPS 目标域名；普通请求最多跟随 3 次重定向，带账号凭据的元数据请求不跟随重定向，不将远程 URL 交给 FFmpeg。连接和单次读取超时均为 15 秒，每个元数据响应最多 2 MiB，完整解析流程总时限为 60 秒；每个视频下载总时限为 10 分钟、大小上限为 512 MiB。超限、空响应、截断、非视频内容、磁盘写入失败均报告错误。失败和取消清理未完成文件。
- 需要联网，新增普通 `INTERNET` 权限，不申请媒体库或全盘存储权限；不在运行时下载 FFmpeg、执行程序、原生库或编解码器，本地 GIF 转换仍可离线使用。

X 的网页及接口并非稳定的下载 API，可能变更、限流或不返回全部媒体；登录也不能恢复已删除内容、取得作者未授予的访问权或解除账号限制。没有 MP4 直链、只返回 HLS 或外部播放器的内容不会下载，不跟随引用推文或第三方视频。失败会保留可编辑的链接或在结果页列出失败原因。解析方式参考 [yt-dlp 官方 Twitter 提取器](https://github.com/yt-dlp/yt-dlp/blob/master/yt_dlp/extractor/twitter.py)；具体支持以 X 当时返回的信息为准。

## 验证

离线测试使用固定元数据、网络替身和测试视频，覆盖链接与不合法域名、视频序号与歧义输入、当前视频/全部视频选择、选择前不下载、取消选择、混合图片/视频的位置匹配、无效媒体位置、单视频直接下载、最高质量选择、多媒体、GIF、无视频、网络错误、大小/截断限制、取消清理、文本分享、应用专属保存、用户目录补存与失败重试，以及下载结果直接通过 FFmpeg 转为 GIF。真实公开接口连通性另行验证，不作为可重复单元测试的网络依赖。

登录相关回归应覆盖明确登录限制、删除、保护、地域与年龄限制、空占位信息和未知原因；确认引用推文或其他推文的状态不能触发当前推文登录。还需验证匿名失败后的官方网页诊断、登录前不下载、拒绝／取消登录、登录成功后重试及范围选择、失效会话重新判断、登录后仍受限不循环弹窗、新导入保护，以及持久会话清除和配置重建。覆盖完成登录后销毁 ViewModel／重建存储对象仍可恢复、恢复完成前点击下载或清除、普通请求失败保留会话、明确失效清除持久记录、保存失败明确报错、取消登录忽略迟到的完成回调；以测试会话在独立进程间检查保存与读取。用两个同时存活的 ViewModel 验证：一个清除登录态后，另一个下次下载不使用旧会话；一个完成登录后，另一个下次操作可读取新会话。登录布局使用离线网页验证说明文字及展开／收起按钮均不存在、加载／错误提示与网页和操作区不重叠，并覆盖大字体、短视口与键盘空间变化；延迟本地网页资源验证 WebView 创建后仍显示加载提示、主文档完成后结束提示；另通过平台错误回调模拟验证主文档 HTTP 错误结束提示，子资源 HTTP 错误不提前结束主文档加载。主动登录需要验证入口可用、取消保留链接、完成后不自动下载，以及后续由用户开始的下载复用会话。

网络与会话安全测试覆盖响应上限、超时、取消断连、重定向拒绝、非官方域名、Cookie 重复／缺失／换行与长度校验、凭据不外发、会话值不出现在字符串表示中、WebView 导航限制与备份排除、磁盘密文不含 Cookie 明文、密文损坏检测及清除后无法恢复。常规自动化测试不使用真实账号；X 登录页面、双重验证、年龄设置和实网下载需在 Android 16 设备上另行人工验证，构建或离线夹具通过不代表这些实网交互已经通过。

`TwitterLiveAccessTest` 是显式启用的联网检查：仅传入仪器测试参数 `twitterLiveAccessCheck=true` 时，才通过实际 Android 网络层验证上述示例的匿名登录限制识别。常规回归会跳过它；若推文或 X 接口发生变化，应先重新确认真实状态，不能为保持测试通过而把空占位信息归为登录限制。

`TwitterSessionProcessTest` 使用独立测试文件和虚构 Cookie 检查实际跨进程恢复：对该测试类分别传入仪器测试参数 `twitterSessionProcessStep=seed` 和 `twitterSessionProcessStep=verify`，分两次启动仪器测试。第二次检查进程编号已变化、会话可解密恢复，并清除测试文件和密钥；常规设备回归跳过此检查。

### 登录首屏诊断（2026-11-12，1.3.4 已修复）

实网检查确认，旧入口 `/i/flow/login` 和 `/login` 均转到 X 新的 `/i/jf/onboarding/web?mode=login`。该页面先建立导航外壳，再异步取得登录步骤；本次还观察到自动通行密钥步骤请求，测试 WebView 未提供 `PublicKeyCredential`。网页内部的后退按钮属于 X，实际点击后返回 `/` 的公开入口。从公开入口点击「登录」可正常显示登录选项。

旧实现同时在创建 WebView 后立即撤下原生加载提示，使网页仍在初始化时没有加载反馈。现在先打开公开入口，并跟踪主文档加载状态；登录页移除了常驻说明文字，为网页保留更多空间。测试设备上未稳定复现用户所述的持续黑屏，因此不能把自动通行密钥探测断言为唯一根因；实网回归需检查全新浏览器数据下的首页、点击登录后的表单和验证步骤。不要用伪造 User-Agent、注入登录脚本、放开外部导航或猜测的登录参数处理此问题。

### 登录表单视口诊断（2026-11-12，1.3.4 已修复）

后续检查发现了独立于加载反馈的表单布局问题：WebView 未设置原生 `LayoutParams`，Compose 的 `AndroidViewHolder` 添加子视图时使用了 `WRAP_CONTENT`。Chromium 在该高度模式下会将 CSS 布局视口高度置为零，即使外层 WebView 已有非零尺寸。实测初始网页外层高 2084 px、`innerHeight` 为 794 CSS px；进入登录并自动打开键盘后，`innerHeight` 为 499 CSS px，但 X 的 `height: 664px; max-height: calc(100dvh - 32px)` 表单被计算为高度和最大高度均为零，内部滚动区仅剩约 16 CSS px。

修复在首次加载与挂载前显式设置 WebView 宽高为 `MATCH_PARENT`，同时启用 `useWideViewPort = true` 和 `loadWithOverviewMode = true`，保留已有的有界布局、裁剪和系统栏／键盘边距处理。Android 的官方最佳实践也要求避免 WebView 使用 `WRAP_CONTENT`，并正确处理网页的视口声明，参见 [Web 应用最佳实践](https://developer.android.com/develop/ui/views/layout/webapps/best-practices)。

回归必须使用实际 `TwitterLoginDialog` 及生产 WebView 设置，加载带 viewport 声明、`100dvh` 和内部滚动表单的离线页面，同时比较原生视图尺寸与 DOM 计算尺寸；只检查 Compose 外层边界不足以发现此问题。还需打开真实系统键盘，确认输入框可见、可通过触摸滚动到提交按钮，关闭键盘后 CSS 视口恢复，并覆盖显式网页视口宽度。

本次 Android 16 模拟器验证中，修复前的离线 `100dvh` 元素高度为 0，修复后与约 794 CSS px 的可见区域一致；WebView 133 与官方 Chromium WebView 160 测试构建均通过真实弹窗、触摸滚动和键盘开关测试。新版引擎上的 X 实网检查显示，键盘打开时表单及滚动区约 467 CSS px，可滚动到「继续」；关闭键盘后表单恢复为 664 CSS px。实网检查仅使用未登录页面，未输入账号信息。用户于 2026-11-12 在 Pixel 11 Pro 上确认修复后的登录页面显示正常；此确认仅覆盖页面显示，不代表完整账号登录、双重验证或登录后下载流程已通过验证。
