# 下载推特(X)视频(GIF)

用户提供推特(X)的推文链接，如果它带有视频(GIF)则下载，并保存到输出目录。（注意：输出目录也请遵循 output_storage.md 的规则与限制）

下载完成的页面，提供「视频转 GIF」的功能按钮，可以将刚下载的视频直接转换成 GIF，让两个功能可以串联起来。

带 `/video/序号` 链接的下载范围选择已加入开发版，尚未发布，记录于 [CHANGELOG 的 unstaged 条目](../CHANGELOG.md#unstaged)。

## 使用流程

1. 首页“图片”分类中选择“下载推特视频（GIF）”（位于“图片拼接”之后），粘贴一条公开推文链接；也可从 X、浏览器等应用分享文本到同名 Natsuko 分享目标。
2. 链接可带分享文案和查询参数，支持 `x.com`、`twitter.com` 及其 `www`、`mobile`、`m` 子域的 `/用户名/status/编号`、`/i/status/编号`、`/i/web/status/编号`、`/statuses/编号`，也接受末尾的 `/video/序号` 或 `/photo/序号`。输入文本最多 8192 个字符；相同链接去重，一次输入多个不同推文链接，或同一推文的不同 `/video/序号` 链接时会报错，不会静默选择其中一个。同一推文的普通链接与单个视频链接同时出现时，保留该视频的定位信息。不支持 `t.co` 短链接、用户主页、搜索页或直接视频地址。
3. 点击“开始下载”，先解析可获取的媒体。链接带 `/video/序号` 且推文包含多个视频或 GIF 时，弹窗选择“只下载当前视频”或“下载全部视频”；确认前不会下载视频或创建输出批次目录，取消弹窗返回输入页并保留链接。推文只有一个视频时直接下载，不额外弹窗；普通推文链接和 `/photo/序号` 链接继续下载推文中的全部视频。下载时显示当前视频、字节进度与校验状态，允许取消；多个视频分别保存并报告单个视频的失败。取消会放弃本次下载批次，清理尚未交付到结果页的文件，保留输入链接供重试。
4. 完成页可打开、分享视频，查看实际保存位置或修改链接继续下载。X 的 GIF 动图按平台提供的 MP4 保存，下载阶段不转码。
5. 每个成功视频都有“视频转 GIF”按钮，点击后直接进入现有 GIF 参数配置页，无需再次选择文件；支持帧率、采样间隔、尺寸与循环设置。使用保留的应用专属视频副本，转换不删除源视频。配置页返回可恢复原下载结果并选择其他视频。

`/video/序号` 按推文原始媒体附件位置匹配，图片也占用这个位置序号；例如依次为图片、视频、视频时，`/video/3` 指向第二个视频。序号不存在或对应的是图片时，明确报告无法找到指定视频，不会自动下载另一个视频；可改用不带媒体后缀的推文链接下载全部视频。视频是否有可下载的 MP4 不改变它的位置或本次视频数量，缺少 MP4 仍按单个视频报告失败。

分享导入只接受 `ACTION_SEND` 的 `text/plain`，读取 `EXTRA_TEXT` 与 `ClipData.text`，不读取分享的文件 URI。分享后保留下载确认步骤，带视频序号的分享链接使用相同的下载范围选择；处理、等待范围选择或保存期间的新导入不会替换当前任务。当前页面有尚未导出的图片调整时，先询问是否放弃编辑：取消保留编辑并丢弃待导入链接，确认后才进入该链接的下载确认页。无效链接只显示错误，不清除已有编辑。

## 保存规则

- 首先保存到应用专属 `Pictures/Natsuko/DownloadTwitterVideo/<时间戳>/`，文件名为 `twitter_<推文编号>_<视频序号>.mp4`。文件名的视频序号从 1 开始，图片不占用序号；只下载指定视频时仍保留它在推文中的原视频序号，某个视频失败后，后续视频也保留原序号。
- 默认不生成公共副本。开启“保存至用户存储目录”后，自动保存到 `Download/Natsuko/DownloadTwitterVideo/`，或自定义根目录下的 `DownloadTwitterVideo/`，不再增加时间戳目录。
- 结果页开启开关可立即补存本次成品；用户目录失败保留应用专属视频，可逐文件重试，已成功保存的文件不会重复复制。自定义目录仍通过系统目录选择器取得持久读写授权。
- 串联转换产生的 GIF 写入应用专属 `VideoToGif/<时间戳>/`，沿用当前保存设置，用户目录副本直接写入 `VideoToGif/`；原 MP4 继续保留。具体授权、保留和重试行为遵循 [输出存储](output_storage.md)。

## 实现与支持范围

- 使用 X 自家的 `cdn.syndication.twimg.com/tweet-result` 公开嵌入接口解析推文，从 `video.twimg.com` 下载 HTTPS MP4，不使用第三方解析站、账号 Cookie 或 API 密钥。常规视频选择接口返回的最高码率 MP4；同码率时优先较大分辨率。
- 网络代码只负责元数据请求与字节下载。下载先写入临时文件，由共享 `FfmpegVideoEngine.probe` 调用随包 FFprobe 校验有效视频流、尺寸和时长后才作为成品提交，不引入 Android 系统媒体处理路径。
- 文件以流方式写盘，限制 HTTPS 目标域名，每个请求最多跟随 3 次重定向，不将远程 URL 交给 FFmpeg。连接和单次读取超时均为 15 秒，元数据请求总时限为 60 秒、响应上限为 2 MiB；每个视频下载总时限为 10 分钟、大小上限为 512 MiB。超限、空响应、截断、非视频内容、磁盘写入失败均报告错误。失败和取消清理未完成文件。
- 需要联网，新增普通 `INTERNET` 权限，不申请媒体库或全盘存储权限；不在运行时下载 FFmpeg、执行程序、原生库或编解码器，本地 GIF 转换仍可离线使用。

公开接口并非稳定的下载 API，可能变更、限流或不返回全部媒体；私密、已删除、需要认证、地域或年龄受限的内容可能不可用。没有 MP4 直链、只返回 HLS 或外部播放器的内容不会下载，不跟随引用推文或第三方视频。失败会保留可编辑的链接或在结果页列出失败原因。解析方式参考 [yt-dlp 官方 Twitter 提取器](https://github.com/yt-dlp/yt-dlp/blob/master/yt_dlp/extractor/twitter.py)；具体支持以 X 当时返回的信息为准。

## 验证

离线测试使用固定元数据、网络替身和测试视频，覆盖链接与不合法域名、视频序号与歧义输入、当前视频/全部视频选择、选择前不下载、取消选择、混合图片/视频的位置匹配、无效媒体位置、单视频直接下载、最高质量选择、多媒体、GIF、无视频、网络错误、大小/截断限制、取消清理、文本分享、应用专属保存、用户目录补存与失败重试，以及下载结果直接通过 FFmpeg 转为 GIF。真实公开接口连通性另行验证，不作为可重复单元测试的网络依赖。
