# 下载推特（X）图片（尚未发布）

用户提供推特（X）的推文链接，将该推文中的全部图片按原顺序批量下载，并保存到输出目录。（输出目录规则与限制见 [输出存储](output_storage.md)。）

下载完成后，结果页提供「转图片拼接」按钮，可将本次下载的全部图片按原顺序直接送入[图片拼接](image_merge.md)配置页，无需重新选择文件。

## 使用流程

1. 首页“图片”分类中选择“下载推特图片”，粘贴一条推文链接；也可从 X、浏览器等应用分享文本到同名 Natsuko 分享目标（`DownloadTwitterImagesShare`）。
2. 链接规则与 [下载推特视频（GIF）](download_twitter_video.md) 一致，支持 `x.com`、`twitter.com` 及其 `www`、`mobile`、`m` 子域的推文链接（含分享文案、查询参数以及末尾 `/photo/序号` 或 `/video/序号`）；单次仅支持一条推文，最多 8192 个字符。不论链接是否带有 `/photo/序号`，均按推文原始附件顺序下载该推文的全部图片，不再额外弹窗确认下载范围。
3. 点击“开始下载”，先解析可获取的图片元数据。若 X 明确要求登录后查看，询问是否登录；同意后在 X 官方登录页完成登录与验证，再重新获取图片信息。共用同一个加密保存的 `TwitterSession`、主动登录入口、清除登录态及访问错误分类规则。
4. 按推文图片顺序逐张下载、写入临时文件并通过系统 `ImageDecoder` 校验图片完整性与实际格式（JPEG / PNG / WebP / GIF 等）后提交成品。多个图片分别保存并报告单个失败；若某张图片失败，其余图片继续下载并保留各自的原始图片序号。取消会放弃本次下载批次，清理尚未交付到结果页的文件，并保留输入链接供重试。
5. 结果页可打开、分享单张或全部图片，查看实际保存位置或修改链接继续下载；点击「转图片拼接」时，将本次全部成功下载的图片按原顺序传给图片拼接配置页（使用保留的应用专属副本），配置页提供“拼接完成后删除原图片”选择框（默认不勾选）。未勾选、被从待拼接列表移除、单张解码失败未参与拼接，或拼接整体失败／取消时，对应原下载图片继续保留；勾选且拼接成功后，仅删除本次实际参与拼接的原图片的应用专属文件及用户目录副本。从图片拼接配置页或完成页返回时，若仍有保留的原下载图片则恢复原图片下载结果，否则返回首页。

分享导入只接受 `ACTION_SEND` 的 `text/plain`，读取 `EXTRA_TEXT` 与 `ClipData.text`，不解引用分享方提供的文件 URI；导入只打开链接确认页，不自动开始下载。存在未导出的图片调整时，先确认是否放弃编辑。

## 保存规则

- 首先保存到应用专属 `Pictures/Natsuko/DownloadTwitterImages/<时间戳>/`，文件名为 `twitter_<推文编号>_<图片序号>.<扩展名>`。图片序号从 1 开始，按推文中的图片出现顺序编号（视频与动图不占用图片序号）；部分失败时，后续成功图片保留原序号。
- 默认不生成公共副本。开启“保存至用户存储目录”后，自动保存到 `Download/Natsuko/DownloadTwitterImages/`，或自定义根目录下的 `DownloadTwitterImages/`，不再增加时间戳目录；结果页开启开关可立即补存并支持逐文件重试。
- 串联进入图片拼接后产生的 `merged.png` 写入 `ImageMerge` 功能目录并沿用当时的保存设置；默认继续保留原下载图片及其用户目录副本，仅当用户在配置页勾选“拼接完成后删除原图片”且拼接成功后，删除实际参与拼接的原图片及其用户目录副本。

## 实现与限制

- 复用 `TwitterHttpClient`、`TwitterWebMetadata` 与 `SyndicationTwitterVideoSource` 解析 `mediaDetails`、`photos` 兜底字段、`unified_card` 及受限网页/GraphQL 中的 `type == "photo"` 附件；过滤掉视频、动图、外部链接卡片及引用推文媒体，不跟随引用或转发推文。
- 从 `media_url_https` 构造 `https://pbs.twimg.com/media/...` 的原图参数（`?format=<格式>&name=orig`），并在 CDN 对 `orig` 返回 404/410 时回退到经过校验的原始 `media_url_https` 地址；图片下载请求限定 `https://pbs.twimg.com/media/...`，不携带账号 Cookie 或 `Authorization` 头，限制最多 3 次同源安全重定向，单张图片大小上限为 64 MiB、超时 2 分钟。
- 本地使用 `ImageDecoder` 校验图片非空且可解码后才提交成品，并按实际解码格式确定文件扩展名与 MIME 类型。

## 验证

- JVM 单元测试覆盖 `TwitterImageUrl` 域名/路径限制与 `name=orig` 改写、`TwitterHttpClient.downloadImage` 流式写入、大小/类型/空文件/404/非官方域名/重定向拦截及取消清理。
- Android 仪器测试使用离线夹具和真实图片编码验证：多图按顺序解析与混合媒体过滤、`photos`/`unified_card` 回退、GraphQL/SSR 登录限制识别、原图 404 回退、局部失败保留原序号、取消清理、`ImageDecoder` 校验、直接串联 `ImageMergeProcessor` 生成拼接图、分享导入、未保存编辑确认、用户目录保存，以及从结果页点击「转图片拼接」后完成拼接并返回原下载结果（包括“拼接完成后删除原图片”默认不勾选、仅串联时显示、勾选后删除已拼接图片的应用专属及用户目录副本、移除部分图片或部分解码失败时保留未参与拼接的原图、全部删除后返回首页，以及取消或重新选择图片时保留原图）。
