# 图片地理位置信息复制

## 交互流程

1. 进入功能，选择一张带有地理位置的图片。图片必须带有位置信息，不具备条件的图片无法选择。我们后续简称它为源信息图片。
2. 选择完 源信息图片 后，进入批量图片选择界面。这个阶段允许用户选择一批图片。这里对图片是否已具有位置信息不做检查。这一批图片后续简称为 复制目标图片。
3. 选择完复制目标图片后，开始自动将 源信息图片 的地理位置信息复制给 复制目标图片们。

## 复制目标图片处理

复制目标图片如果已经具有地理位置信息，在复制处理到它时，弹出选择框供用户选择。选择框的内容大致如下：

复制前地址：[复制目标图片的位置信息]

复制后地址：[源信息图片的位置信息]

覆盖 跳过 中止

后续全部覆盖 后续全部跳过

## 技术要求

不要安装其它软件来读写图片位置信息，功能需要在本软件中闭环。但可以引用或参考一切开源实现。

需要支持的图片格式：

* JPEG/JPG
* PNG
* WebP
* HEIF/HEIC
* TIFF/TIF
* 索尼 Sony .arw
* 佳能 Canon .cr3/.cr2
* 尼康 Nikon .nef
* 富士 Fujifilm .raf
* 松下 Panasonic .rw2

## 其它说明

* 如果源信息图片中不仅仅具有坐标信息，还具有「地点名称」之类的信息，请一并复制到目标图片。


## 实现说明

### 入口与选择

- 首页「图片」分类提供「复制图片位置」，系统分享面板提供同名目标。
- 使用系统文件选择器以兼容 RAW 文件及不同文档提供者；文件提供者无法按 GPS 元数据筛选，应用在导入后异步校验。没有有效经纬度、格式不支持或读取失败的候选显示原因并禁用，不会进入目标选择或开始复制。
- 单张合格来源校验后自动打开目标多选；多张分享时先从合格候选中选一张来源。分享的是源信息图片，不会直接改写分享图片。取消目标选择时保留来源，可重新选择目标。
- 只读取选中文件实际提供的元数据。发送方移除位置、分享了已脱敏的副本或文件提供者无法读取原始位置时，需通过文件选择器重新选择保留元数据的原文件；不推测或联网补全地点。

### 元数据和输出

- 使用随包内置的 ExifTool 13.53 与 Perl 5.40.2，支持 `arm64-v8a` 与 `x86_64`。运行时不下载工具或编解码器，不调用外部应用，不解码重压缩图片。
- 支持上文全部扩展名；按实际文件类型校验，损坏、不匹配和不可写文件逐项报告失败。
- 复制可写的 GPS 信息与 EXIF/XMP/IPTC 地点信息（包括地点名称、城市、地区、国家等）；不通过反向地理编码生成地址。覆盖会清除目标原有位置再复制来源位置，避免混合两处地址；其他图片内容和非位置元数据保留。
- 同一来源的 IPTC 与 XMP 地点字段若互相矛盾，能同时存储两者的目标会保留两者；目标格式无法无损保留这些冲突信息时，该文件报告校验失败，不静默丢弃或替换其中之一。
- 每次写入后重新读取并校验位置。结果保存为原格式新副本，文件名为批次序号、原名称和 `_location` 后缀，目录为 `Pictures/Natsuko/CopyLocation/<时间戳>/`；原始 URI 文件不修改。
- 用户目录保存沿用全局设置，默认额外保存到 `Download/Natsuko/CopyLocation/`，或已授权目录内的同名子目录。结果页可以查看、打开或分享。

### 冲突、失败和取消

- 目标即使只有地点名称而没有有效经纬度，也视为已有位置并询问；“后续全部”同时处理当前冲突，且只对本批次后续已有位置的图片生效。没有位置的目标仍照常复制。
- “跳过”不生成该文件的副本；“中止”保留此前完成的副本，当前与剩余目标不处理，并在结果页列出状态。策略不会沿用到下一批次。
- 读取、写入、权限和存储失败按文件报告，其余文件继续处理。进度弹窗的“取消”取消整个尚未发布的批次，清理临时及未发布副本并保留来源以便重试。
- 处理和来源校验在后台执行，批次进度可见；冲突弹窗暂停批次等待操作。临时来源及未完成输出在退出、失败或取消时清理；工作流不跨进程重启恢复。


### 验证范围

- `CopyLocationProcessorTest`：单文件导入、批量处理、五种冲突决策、名称位置冲突、逐文件错误、原文件保留及取消清理。
- `CopyLocationWorkflowTest` / `CopyLocationScreensTest`：来源校验与不可选候选、单图/多图分享、自动处理、冲突弹窗、取消重试及用户目录保存。
- `LocationMetadataEngineTest`：在 Android 上调用实际内置运行时，覆盖 11 类格式、Unicode 地点、IPTC 跨格式复制和 XMP 结构化坐标。
- `python3 scripts/test-location-metadata.py`：使用同一桥接脚本验证 11 类容器的图片数据哈希及非位置元数据保持不变。仓库内使用小型元数据容器样本，不能代替所有相机型号和损坏文件组合的兼容性验证；样本来源见 `app/src/androidTest/assets/location/README.md`。
- `python3 scripts/verify-metadata.py <APK或AAB>`：验证两种 ABI、16 KB 对齐、模块、桥接脚本和许可实际随包提供。
