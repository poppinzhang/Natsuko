# 图片调整

## 文档状态与范围

本文记录「图片调整」的需求、交互设计与当前实现。功能已实现，文中的控件数值和默认选项即应用的当前行为；具体实现取舍见[实现说明](#实现说明)。

已确定的核心约束：

- 首页「图片」分类只新增一个入口，名称为「图片调整」。裁剪、旋转、镜像、拉直、缩小尺寸和格式导出都属于同一工作流，不拆成多个首页入口。
- 一次选择并调整一张图片；允许不做任何编辑，直接选择格式和质量导出。
- 「拉直」指小角度旋转整张照片，使台阶、地平线等与辅助网格平行，不包含四角透视校正。
- 改变输出格式或有损压缩质量不得主动缩小像素尺寸。
- 「缩小尺寸」是编辑页中的独立工具，不放在导出设置中。缩小始终锁定当前宽高比，不允许分别拉伸宽高，也不提供放大。
- 每次导出生成新文件，不覆盖原图。预览、试编码和正式成品使用一致的编辑参数与输出尺寸。

用户提供的截图只用于理解交互布局，不复制、嵌入或保存到项目，也不作为应用资源或测试素材。截图中的透视、自动取景、滤镜、标记等其他工具不属于本次需求。

## 入口与主流程

1. 用户在首页「图片」分类点击「图片调整」，打开系统单张图片选择器。
2. 图片读取成功后直接进入编辑页，完整展示图片；取消选择则返回首页。
3. 用户按需使用裁剪、拉直、旋转、镜像和缩小尺寸，实时查看效果与当前像素尺寸。
4. 点击「导出」打开导出设置，选择格式、有损质量以及必要的透明区域背景色。未编辑的图片也可以进入此步骤。
5. 后台计算当前选项对应的输出大小；点击「保存」后提交匹配当前参数的成品，显示处理及保存状态。
6. 完成后进入结果页，提供查看、分享和现有用户目录保存能力；支持返回编辑页继续调整并另存新版本。

导出设置返回编辑页时保留所有操作；再次进入导出设置时保留本次工作流已选的格式、质量和背景色。新选一张图片时重建编辑状态，使用默认导出设置。

退出仍有未导出编辑的工作流时提示是否放弃；从导出设置返回编辑页不弹出放弃提示。导出失败或取消导出不清空编辑状态。

### 分享导入

- 提供一个名为「图片调整」的系统分享目标，导入成功后直接进入同一编辑页，不再要求重新选择图片。
- 复用现有分享导入解析、URI 去重、类型检查和临时读取授权处理。
- 一次只编辑一张。收到多张有效图片时，先让用户选择其中一张，明确说明仅处理所选图片，不静默取第一张；不形成 batch processing（批处理）队列。
- 截图分享进入此功能后同样由用户编辑和导出，不触发 automatic processing（自动处理）。既有「去除黑边」的自动处理行为保持原有约定。
- 无效、不可读取或没有图片的分享内容给出清楚提示，允许返回或重新选择。

## 编辑界面

采用以图片为中心的编辑布局，参考截图的预览区、裁剪边框和底部工具切换方式：

- 顶部提供返回、撤销、重做、恢复原图和导出操作；图标具有明确的无障碍说明。
- 中央为主要图片预览区，支持双指缩放与平移查看细节。查看时的缩放和平移不改变输出尺寸或裁剪范围。
- 裁剪时显示边框、边缘与四角控制点；框外区域变暗。拉直时叠加水平、垂直网格。
- 底部提供「裁剪 / 拉直 / 旋转 / 镜像 / 缩小尺寸」工具栏，当前工具的参数显示在相邻控制区，小屏幕上仍应能访问所有工具与导出按钮。
- 显示当前预计输出宽高，例如「3000 × 2000 px」；几何编辑或缩小比例变化后同步更新。
- 网格、控制点、框外遮罩和界面背景不进入成品。透明图片使用可辨识的透明背景指示。
- 工具切换保留已确认的效果，不要求导出后再进行下一项调整。拖动过程作为连续预览，一次完成的手势形成一个撤销步骤。
- 工具内的重置只撤销该工具当前调整；「恢复原图」清除全部编辑，包括缩小尺寸。撤销与重做覆盖全部编辑工具。
- 适配现有浅色、深色和跟随系统模式，界面颜色不改变图片颜色。所有文案、状态和无障碍说明提供中英文，沿用[国际化约定](i18n.md)。

## 编辑工具

### 裁剪

- 默认自由裁剪，可拖动边缘、四角和裁剪框位置，保留区域必须位于有效图像范围内。
- 提供自由、原图比例、1:1、4:3、3:2、16:9 等比例选项；非正方形比例支持横竖切换。
- 选择固定比例只约束裁剪框，不拉伸图片。自由裁剪可以改变画面的宽高比，因为它移除了边缘内容，不属于非等比缩放。
- 原图比例以正确应用图片方向后的原始宽高为基准；旋转 90° 时裁剪范围与画面一起旋转，相应交换宽高。
- 裁剪范围与输出像素边界使用确定性的取整规则，不能在导出时额外发生未预览的裁切。

### 拉直

- 小角度旋转整张图片，用于将台阶、地平线等与水平或垂直网格对齐。
- 提供角度滑杆与数值，范围为 −45° 至 +45°，步长为 0.1°，默认 0°；支持微调与归零。
- 调整时实时显示辅助网格和最终保留范围。
- 默认自动裁掉旋转产生的未覆盖边角，保持当前裁剪框比例，在有效范围内尽量保留画面；不通过把裁剪后的图像放大回原尺寸来掩盖裁边。
- 已有裁剪框越出旋转后的有效范围时，实时显示自动收紧后的范围，不能等到导出才额外裁边。归零移除拉直造成的额外裁边，但保留用户主动设置的裁剪范围。
- 0° 不引入额外裁剪。原图自带的透明区域不是旋转空白边角，不因此自动移除。
- 拉直不是透视校正，不提供四角投影、水平或垂直透视滑杆、纸张识别。

### 旋转与镜像

- 旋转提供顺时针和逆时针 90°；90°/270° 交换宽高，180° 不改变宽高。
- 镜像提供左右翻转和上下翻转，以用户当前看到的画面方向为准，不改变像素尺寸。
- 操作在当前编辑结果上生效，裁剪选择随画面正确变换；切换工具不重置其他调整。

### 缩小尺寸

- 此工具只出现在编辑页。导出页可以只读显示最终宽高，不提供分辨率、尺寸倍率或其他隐式缩小选项。
- 默认 100%，表示不额外缩小；提供 75%、50%、25% 快捷比例，并允许输入目标宽度或目标高度。
- 宽高始终联动：输入其中一边后，另一边根据当前图片比例自动计算。没有解锁比例或独立拉伸宽高的入口。
- 目标尺寸必须为正整数，且不得超过当前几何编辑结果的尺寸。整数像素取整可能产生不足一个像素的计算误差，不引入独立的横向或纵向缩放参数。
- 比例以完成裁剪、拉直、旋转和镜像后、尚未缩小的有效尺寸为基准。自定义宽度或高度也转换为同一个缩小比例。
- 后续继续裁剪或旋转时，保持已选缩小比例，重新计算宽高，并更新尺寸显示；不锁死旧的自定义宽高而拉伸新画面。
- 多次改变比例都从源图和编辑参数重新生成结果，不连续缩小已缩小的位图。恢复 100% 是恢复源图可提供的有效尺寸，不是把缩小后的位图插值放大。

例如，4000 × 3000 px 图片选择 50% 后为 2000 × 1500 px；若随后裁成 3000 × 3000 px 的有效区域，结果变为 1500 × 1500 px。切换 PNG/JPEG 或改变质量时，这些尺寸均保持不变。

## 导出设置

### 格式与质量

| 输出格式 | 设置 | 透明区域 |
| --- | --- | --- |
| PNG | 无损，不显示质量百分比 | 保留透明度 |
| JPEG | 60%、75%、85%、95%、100%；默认 85% | 合成背景色，默认白色 |
| WebP | 有损或无损；有损使用上述质量档位，默认 85% | 两种模式均保留透明度 |

- PNG、JPEG 输入默认选择同格式输出。WebP 输入默认选择 WebP 无损，不尝试推断并复刻原编码质量。
- 其他受支持的静态输入，有透明度时默认 PNG，否则默认 JPEG。格式和扩展名、MIME 类型必须匹配。
- UI 使用「导出质量」。百分比是编码参数，不代表保留相同比例的原始画质或文件字节数；JPEG 100% 仍是有损编码，不标为无损。无损模式不提供误导性的画质百分比。
- 有透明像素且选择 JPEG 时显示背景色选项，首版提供白色和黑色，并在预览中同步呈现合成效果。
- 只改变格式、质量、背景色或元数据处理，不改变编辑结果的像素宽高。无论是否编辑，都允许导出。
- 同格式且无编辑时仍按当前设置重新编码，不承诺原文件字节完全一致，也不承诺文件一定变小。需要像素保真时，应选择适合的无损输出；无损编码不撤销已有的几何插值、颜色转换或源文件有损压缩。

### 输出大小

- 展示原文件大小（可获取时）、最终像素宽高以及当前选项的预估输出大小；最终大小未就绪时显示「正在计算」。
- 只为当前选项计算大小，不要求一次预编码所有质量档位。快速切换设置时合并连续请求，优先完成最新选择。
- 对最终编辑结果，使用最终尺寸、格式、质量、透明区域背景色和元数据规则在后台试编码到应用私有临时文件。不得用缩略图文件大小按比例外推作为准确结果。
- 计算完成后读取完整临时文件字节数；显示可使用 KB/MB 的四舍五入值。此时数值已来自实际编码文件，成品提交同一份文件，不再用另一套参数重编码。
- 编辑参数或导出设置变化后，立即将旧临时文件和大小标记为过期；旧任务的延迟结果不能覆盖当前状态。
- 用户可以在计算期间点击保存，此时显示等待或编码进度，直到匹配当前参数的结果就绪。不能导出上一组参数的临时文件，也不能在保存前自动降低质量或尺寸。
- 缓存只服务当前工作流；取消、失效或离开后清理无用临时文件。未点击保存的试编码结果不出现在用户目录或成品列表中。

## 输入、保真与性能边界

- 首版处理静态单图，至少覆盖 PNG、JPEG 和静态 WebP；HEIC/HEIF、BMP 等其他静态图片以平台实际可解码能力为准，文件类型声明通过后仍需验证内容。
- 动态 GIF、动态 WebP 等动画输入明确提示暂不支持，不能静默只导出第一帧；不加入动图编辑能力。
- 正确应用 EXIF 方向后再计算尺寸、裁剪和变换。预览与导出采用同一方向与颜色处理策略。
- 首版采用普通 sRGB/SDR 输出，不承诺保留广色域或 HDR。涉及转换时在导出说明中明确提示；不能只删除色彩描述而把原颜色值当作 sRGB 使用。
- 默认不复制拍摄位置、设备和拍摄时间等原始 EXIF 信息；方向已写入像素后不得再复制会造成重复旋转的方向标签。输出保留正确解读成品所需的格式及颜色信息。
- 预览允许使用较小的解码尺寸，正式处理以源图和全部编辑参数生成。不得将预览图用作最终成品，也不得直接沿用当前通用 `BitmapLoader` 的 4096 px 默认缩小策略。
- 保存编辑参数与轻量历史，不为每次操作保留完整大位图；导出时尽可能合并几何变换，避免逐步压缩或重复重采样造成累积损失。
- 读取、解码、试编码和文件保存不阻塞 UI；耗时阶段显示状态并允许取消。能可靠测量时显示进度，无法测量时使用明确的阶段提示。
- 超大图的像素、边长和峰值内存上限需通过目标设备验证后记录，不直接套用其他功能的限制。超限时明确报告原因；如果可通过用户主动使用「缩小尺寸」解决，则引导回该工具，不能因资源不足自动缩小。
- 同一几何计算结果必须用于预览范围、尺寸展示、试编码及正式导出；导出参数快照与缓存版本绑定，避免并发更新串用结果。

## 保存与错误处理

沿用[输出存储](output_storage.md)的应用专属副本、用户目录开关、结果页补存与失败重试约定：

- 规划的应用专属目录为 `Pictures/Natsuko/ImageAdjustment/<时间戳>/`。
- 默认用户目录为 `Download/Natsuko/ImageAdjustment/`；自定义根目录下直接使用 `ImageAdjustment/`，不添加用户可见的运行时间戳目录。
- 文件名以安全化并限长的原文件名为基础，加 `_adjusted` 和所选格式扩展名；重复导出或遇到同名文件时分配唯一名称，不覆盖原图或先前成品。
- 编辑结束并点击保存后才提交成品。应用专属写入成功但用户目录保存失败时保留成品，允许查看、分享、更改目录或重试保存，无需重新编辑和编码。
- 损坏或不支持的文件、URI 权限失效、存储空间不足、解码或编码失败均给出明确提示。处理失败保留可恢复的编辑状态，清理不完整输出。
- 正式导出中取消时清理未提交文件；已经完成的成品不因后续取消或离开被删除。
- 本功能复用现有导入、输出与结果展示层，不改变其他功能的批处理和自动处理规则。配置变化和中英文切换应保留当前工作流；不要求首版提供跨应用重启的草稿库。

## 实现说明

### 代码结构

- `processing/ImageAdjustmentGeometry.kt`：不依赖 Android 的几何计算（`AdjustmentGeometry`）与编辑操作（`AdjustmentEditing`），由 JVM 单元测试覆盖。
- `processing/ImageAdjustmentProcessor.kt`：预览解码、按需区域解码与单次重采样、试编码和成品提交；`ImageAdjustmentSession` 管理本次工作流的渲染缓存与临时文件。
- `ui/ImageAdjustmentState.kt` 与 `NatsukoViewModel`：工作流状态、撤销历史、大小估算与保存调度。
- `ui/ImageAdjustmentScreens.kt`、`ui/ImageAdjustmentCanvas.kt`、`ui/AdjustmentIcons.kt`：选图、编辑、导出页面，预览绘制与手势，以及内置的轮廓图标。

### 编辑参数与几何

- 编辑状态只保存参数：顺时针 90° 旋转次数、镜像标志、以 0.1° 为单位的整数拉直角度、裁剪矩形、裁剪比例与横竖方向、缩小比例。撤销历史最多保留 100 步，不保存位图。
- 「画框」指应用 EXIF 方向、镜像和 90° 旋转后的图像。拉直在画框内绕中心旋转画面，裁剪框始终与画框坐标轴对齐。镜像和旋转按用户当前看到的方向折算为同一组参数；翻转同时镜像裁剪框并反转拉直角度。
- 预览、尺寸显示、试编码和导出都调用同一个 `AdjustmentGeometry.resolve`，再由一个仿射变换把源像素映射到成品，导出只重采样一次。
- 裁剪以整数像素保存。手势结束时四舍五入；若取整后触及旋转产生的空白边角，则改为向内取整。成品宽高为编辑后尺寸乘缩小比例后各自四舍五入一次，至少 1 px，且不超过编辑后尺寸。
- 拉直自动裁边：0° 时直接使用用户裁剪；其他角度下，裁剪框若超出旋转后的画面，则保持其宽高比，在用户裁剪框内选取面积最大、且尽量靠近原中心的矩形，再向内取整。裁剪框完全落在空白角落时，改为在整个画框内寻找同比例且不超过原尺寸的矩形。归零后恢复用户裁剪。
- 选择固定比例时，以当前裁剪中心为准，取画框内该比例的最大矩形。「原图比例」按 EXIF 方向后的原始宽高计算，奇数次 90° 旋转后自动显示为竖横互换的比例。

### 交互

- 裁剪框支持拖动四角、四边和整体移动；控制点在屏幕上至少相距 32 dp。固定比例时沿对角线等比缩放；到达有效范围时停在边界，另一方向继续跟随手指。拖动中实时预览，抬起手指记录一个撤销步骤。
- 双指缩放（最高 8 倍）与平移只改变查看，双击恢复；出现第二个手指时取消正在进行的裁剪拖动。拉直滑杆连续预览，松手记录一步；±0.1° 按钮每次记录一步。
- 工具重置：裁剪恢复全幅与自由比例；拉直归零；旋转重置保留镜像；镜像重置保留旋转。「恢复原图」作为一个可撤销步骤清除全部编辑。
- 缩小尺寸的宽度、高度输入框相互联动，点击「应用」或键盘完成后才换算为缩小比例；输入超出 1 至编辑后尺寸的范围时提示错误。
- 横向且宽度不小于 600 dp 时，控制区位于预览右侧；其他情况下位于预览下方。
- 结果页提供「继续调整」，返回编辑页并保留全部参数，可另存新版本。

### 导出、大小估算与保存

- WebP 无损使用固定的压缩力度 75，相同参数总是得到相同字节。
- 比较导出参数时，归一化不影响成品的选项（例如 PNG 的质量值），这些变化不会使已完成的大小失效。参数变化后立即显示「正在计算…」，300 ms 内的连续变化合并为一次编码，旧任务的结果不会写入当前状态。
- 试编码写入应用缓存目录 `image-adjustment/session-*/`，以完整文件的字节数作为预估大小。保存时提交同一份文件（移动或复制后核对字节数）；编码尚未完成时等待其结果。成品位于 `Pictures/Natsuko/ImageAdjustment/<时间戳>/<原文件名>_adjusted.<扩展名>`。
- 离开导出页时释放渲染位图；开始新工作流、返回首页或 ViewModel 清理时删除临时目录。新会话启动时清理之前进程遗留的临时目录。
- 预览中检测到透明像素时才显示 JPEG 背景色选项。源图带 alpha 通道时，JPEG 导出总会按所选（或默认白色）背景合成，避免缩小的预览遗漏个别透明像素。

### 解码、颜色与限制

- 预览以最长边 2560 px 解码并转换为 sRGB，只用于显示，不作为成品。
- 导出重新读取源文件：只解码成品覆盖的源区域（外扩 1 px）；缩小导出时以成品分辨率的 2 倍解码后再一次缩放；只有整数裁剪而无旋转、镜像、拉直和缩小时，直接输出解码像素。
- 解码时转换到 sRGB，输出 8 位 sRGB；HDR 增益图会被移除，导出页对广色域或 HDR 图片给出转换提示。`Bitmap.compress` 不写入 EXIF，成品不含位置、设备、拍摄时间和方向标签。
- 初始上限：单个位图不超过 5200 万像素（可原尺寸处理 8160 × 6144 的 50 MP 照片），解码区域与成品合计不超过 8000 万像素（ARGB_8888 约 320 MB）；WebP 每边不超过 16383 px。超限或内存不足时说明原因并提供「缩小尺寸」入口，不会自动缩小。上述数值已在 Android 16 模拟器上以常规尺寸验证，尚需在目标实体设备上测量峰值内存后再调整。
- 动画 GIF、动画 WebP 等由 `ImageDecoder` 的动画标记识别并提示暂不支持；损坏或无法读取的文件在编辑页显示错误，可返回或重新选择。

### 分享导入

- `ImageAdjustmentShare` 接收 `image/*` 的 `ACTION_SEND` 与 `ACTION_SEND_MULTIPLE`。单张直接进入编辑页；多张进入选图页，只处理所选的一张，不形成批处理队列，也不触发自动处理。
- 编辑页或导出页存在未导出编辑时，新的选择或分享导入先询问是否放弃，确认后才进入新工作流。

## 验收要点

下表行为由 JVM 单元测试 `ImageAdjustmentGeometryTest` 和设备测试 `ImageAdjustmentWorkflowTest`、`ShareImportParserTest`、`UserStorageRepositoryTest` 覆盖；浅色、深色界面与各编辑页另经模拟器截图检查。大图上限的峰值内存尚未在实体设备上验证。

| 场景 | 预期结果 |
| --- | --- |
| 首页及单图导入 | 「图片」分类只有一个「图片调整」入口；选择一张后直接进入编辑页 |
| 单图和截图分享导入 | 直接进入同一编辑页，不重新选图、不自动导出 |
| 多图分享与无效载荷 | 明确选择其中一张或显示错误，不静默丢弃、不崩溃；已有多图功能仍按原流程工作 |
| 无编辑，PNG → JPEG | 宽高保持不变，格式与 MIME 正确，原文件不变 |
| 仅切换有损质量 | 宽高、裁剪范围和缩小比例不变；大小更新，允许新文件比原文件大 |
| 自由与固定比例裁剪 | 预览和输出范围一致，固定比例不拉伸图像 |
| 拉直 ±角度、归零及已有裁剪 | 网格与角度同步；自动裁边可见，0° 不额外裁边；归零不撤销主动裁剪 |
| 90° 旋转及两个方向的镜像 | 朝向、边界、宽高交换正确，组合后预览与输出一致 |
| 缩小尺寸与自定义单边 | 仅编辑页可操作；宽高联动，尺寸为正整数，不允许放大或独立拉伸 |
| 缩小后继续裁剪、旋转或恢复 100% | 使用同一比例重新计算尺寸，不累积缩小损失，不把旧宽高强加给新比例 |
| 透明图导出 | PNG/WebP 保留透明度；JPEG 按选定背景合成且预览一致 |
| 快速改变选项并保存 | 旧大小立即失效，最终文件对应最新确认参数，字节数与试编码结果一致 |
| 撤销、重做、重置和页面返回 | 覆盖全部编辑；工具重置与恢复原图区别明确；返回后参数完整保留 |
| EXIF 方向、颜色转换与元数据 | 显示方向与导出一致，尺寸按正确方向计算，不重复旋转，不复制位置元数据 |
| 大图、损坏图片、动画输入 | 明确报告限制，不静默缩小或取第一帧，UI 保持响应 |
| 编码失败、保存失败与取消 | 编辑可继续，未完成文件清理，已完成副本保留并可重试用户目录保存 |
| 外观、语言与无障碍 | 中英文及浅深色可用，图标说明齐全，切换配置保留编辑状态 |
