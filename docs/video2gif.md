# 视频转 GIF

## 支持范围

应用内置从官方源码构建的 FFmpeg 与 FFprobe，使用软件解码器处理 MP4、MKV、MOV、WebM 等常用容器，以及 H.264、H.265、AV1 等常用视频编码。后端与所需组件随安装包提供，安装后即可离线使用，无需运行时下载。当前原生架构为 `arm64-v8a` 和 `x86_64`；具体版本、启用组件、来源与校验信息见 [FFmpeg 构建资料](../third_party/ffmpeg/README.md)。

视频元数据探测、解码、采样、缩放、滤镜与 GIF 编码全部通过共用的 `FfmpegVideoEngine` 执行。后续新增视频资源处理功能同样使用此后端。损坏文件、无可解码视频流或未包含的格式会报告错误；不保证任意编码配置的视频均能处理。

## 参数

- 播放帧率：1–30 fps，决定 GIF 每帧显示时间。
- 视频采样间隔：50–1000 ms，决定从源视频抓取画面的时间点。
- 最大宽度：360、480、720、1080 px，保持视频显示比例、不放大小视频；输出高度另有 4096 px 安全上限。
- 循环次数：无限、1 次或 3 次。
- 帧数保护：最多 300 帧；长视频会自动增大实际采样间隔，使采样覆盖整段视频。

播放帧率与视频采样间隔相互独立。例如，采样间隔为 200 ms、播放帧率为 10 fps 时，每秒源视频大约选取 5 帧，这些帧会在 GIF 中播放约半秒。GIF 帧延迟以百分之一秒为单位，实际播放时间有相应的取整误差；最后一帧也按所选播放帧率保留显示时间。

## 处理流程

也可在“下载推特视频（GIF）”完成页点击某个视频的“视频转 GIF”，直接进入本功能配置页，无需再次选择文件。使用已下载的应用专属副本，用户目录授权失效不会阻止串联；转换成功、失败或取消均不删除源视频。配置页返回时可回到原下载结果继续选择其他视频。

1. 从系统选择器或分享导入接收单个视频，在后台将 URI 内容流式暂存到应用私有缓存目录；支持没有本地文件路径的文档 URI。
2. 使用 FFprobe 读取视频时长、尺寸等元数据，计算覆盖整段视频的采样计划。
3. 第一次 FFmpeg 处理从整段视频均匀采样最多 32 帧代表画面，缩小到宽高均不超过 160 px，通过 `palettegen` 生成适合当前视频的全局调色板，最多 256 色。
4. 第二次 FFmpeg 处理按用户配置的尺寸和采样计划生成最多 300 帧，通过 `paletteuse` 应用调色板和 Sierra 颜色抖动，并设置播放帧率及循环次数，写入 GIF。第一遍的分析尺寸和帧数限制不会降低成品的配置尺寸或帧数。
5. 成功后按输出设置保留或另存成品；临时输入和调色板在成功、失败或取消后均清理。取消会终止 FFmpeg 进程，失败或取消不会保留未完成 GIF。

处理期间显示进度并允许取消。两遍处理避免缓存整段已解码画面，但都会读取和解码源视频以取得采样画面；暂存输入需要与源文件大小相当的可用缓存空间。调色板分析只接收最多 819,200 个像素样本，从而限制颜色直方图的增长；解码器和后续处理的内存占用仍取决于源视频及输出尺寸。

GIF 本身最多支持 256 色，自适应调色板和抖动能改善颜色表现，仍不能保留原视频的全部颜色。调色板由代表画面生成，极短暂出现的特殊颜色可能没有被分析到。当前不支持多视频批处理。

## 输出

默认输出目录：应用专属 `Pictures/Natsuko/VideoToGif/<时间戳>/`。开启“保存至用户存储目录”后，成品自动保存到 `Download/Natsuko/VideoToGif/` 或自定义目录下的 `VideoToGif/`，不再增加时间戳目录；也可在处理完成页开启开关并立即补存本次结果。详见 [输出存储](output_storage.md)。
